# Rongu–Bondhu Behavior Parity Audit

Audit date: 2026-11-22. This document compares the checked-in local Mati Kohon bundle with KrishiBondhu's existing companion. It records source evidence separately from browser evidence. No Rongu source, art, branding, or assets were copied.

## Inspection and verification limits

- Inspected the local reference bundle under `krishi_client/public/matikohon/`, especially `companion.js`, `companion.css`, `companion-stories.js`, `mascot/rongu.js`, and `mascot/rongu-motion.js`.
- The hosted `https://matikohon.vercel.app/` could not be loaded in the web viewer. Browser observations below are from the local bundle served through the KrishiBondhu preview, not the hosted site.
- Used real Chrome against `http://localhost:3000/` and the local reference page. The local reference landing greeting/menu and first tour step were visually observed. KrishiBondhu's compact character interaction, tour start, target spotlight, transition to `/dashboard`, and step 2 of 5 were observed in the prior browser run at about 648px. In this follow-up, a clean Incognito homepage displayed the actual shaded Three.js dragon; a first-visit greeting appeared in the first clean session, and clicking the character opened the compact menu while the assistant panel remained closed. Chrome `chrome://gpu` reported `WebGL: Hardware accelerated`; no `[BondhuMascot]` initialization error or React `removeChild` error appeared in DevTools. The transparent canvas was visually distinct from the page and had no rectangular backdrop.
- The earlier SVG-only capture's exact cause could not be reconstructed. Current evidence rules out Chrome-wide WebGL disablement for this installation, and the current normal-motion path succeeds. The code selects SVG before renderer initialization, on caught initialization failure, on context loss, or while the mascot is inactive (hidden/motion disabled). No initialization error appeared in the successful run. Do not infer which condition applied to the earlier capture.
- Saved actual Chrome screenshots (not mockups) in `browser-evidence/`: `bondhu-home-alone.jpg` and `bondhu-contextual-help.jpg`. Both show the Three.js model; the latter shows the compact contextual menu. The first-visit greeting and tour spotlight were observed live but their screenshots were not saved as files. Chrome DevTools device emulation was set to 390×844, but fit-to-window scaling and intermittent capture prevented a reliable full visual audit or saved mobile screenshot. 360/768/1024/1440 were not browser-tested. DevTools also showed backend `401` auth and `503` soil-moisture requests; these are not Bondhu/WebGL errors.

## KrishiBondhu changes in this correction

- Kept a single `MiniGuide` and existing Three.js mascot and tour infrastructure.
- Made the assistant panel an explicit route; the floating character opens a compact speech bubble instead of a large persistent widget.
- Added a first-visit homepage greeting that respects the saved hidden preference, plus dismissal and focus/hover handling.
- Added responsive character bounds, persistent drag placement, adaptive bubble placement, a narrow-screen tour sheet, and page-wide gaze tracking.
- Softened the original Bondhu material response, added gaze groups to the existing model, and kept the original dragon design. No static image replaced the model.
- Added regression checks for first-visit behavior, no permanent panel, saved hide/drag behavior, responsive bubble geometry, and mobile preferred placement.

## Remaining gaps

This is a behavior-alignment correction, not complete Rongu parity. Bondhu does not have the landing-hero stage, full flight/action animation engine, petting gestures, per-role tour offers/role switching, chapter chooser, custom scrolling engine, continuous page anchors, or full pointer/keyboard tour parity. The Three.js dragon is visually verified in Chrome at the available narrow window size, but it still uses lightweight primitive geometry rather than a sculpted model. Drag persistence, hide/restore/reload, language switching, assistant launch, voice playback, reduced motion, and mobile touch were not verified in this follow-up browser run. Exact viewport-width screenshots and an active-tour screenshot file remain unavailable.
